# Todo 3.0 升级与验证

重复任务从「完成本次后创建下次」改为「在计划日期出现」。完成或取消完成只改变本次状态。

## 发布顺序

1. 在 Supabase SQL Editor 打开并执行整份 `lib/supabase/migrations/20261002_todo_recurrence.sql`。它依赖现有 Todo 2.0 表；全新数据库先执行 `lib/supabase/schema.sql`。
2. 看到执行成功后，再推送这次前端改动，让 EdgeOne 发布新版本。
3. 发布完成后刷新网页，避免旧页面继续按旧规则操作重复任务。迁移与发布之间暂停修改重复任务。

不要重跑旧的 `schema.sql` 来升级：Todo 3.0 用原定日期识别每次重复，旧脚本会尝试恢复按截止日期去重的索引，可能与已改期的任务冲突。

迁移使用事务，新字段和函数可以重复执行；它会把现有重复任务转为计划模板，保留原有任务、完成状态、优先级与计划时间。重复执行不会重新启动已经停止的计划。迁移不会删掉现有学习资料或分析报告，也不需要增加环境变量。

## 使用规则

- **每天**：每天都有独立状态；昨日未完成不会阻止今天出现任务。
- **周一至周五**：仅星期一到星期五；在周末创建会从下周一开始。这里的规则不读取法定节假日日历。
- **每周**：在开始日期对应的星期几出现。
- **仅这次**：修改内容、日期、时间或优先级。原定日期仍用来识别本次，因此改期后原日期不会再自动补出一条。
- **这次及以后**：从所选任务的原定日期开始更新内容、时间、优先级与规则；未完成的后续单次修改会被替换，已完成记录和跳过日期保留。选择「不重复」会保留本次任务并停止后续生成。
- **跳过这次**：不计入当日进度；在该日期的「已跳过」分组中可恢复。
- **停止这次及以后**：移除本次及以后尚未完成的任务，已完成记录保留。与「跳过」不同，恢复某一条历史记录不会重启计划。
- **逾期**：今天的逾期区展示单次任务和最近 30 天的重复待办。长期未打开时只补齐最近 30 天；打开更早或更晚的日期，可以查看当天的计划。计划时间用于标记安排，尚不支持通知提醒。

任务实例与重复计划通过 Supabase RLS 按用户隔离，创建、编辑、停止通过事务函数提交，避免前端分步写入只成功一半。多个页面读取同一计划时，锁和唯一索引保证不重复生成。

## 检查

本地执行：

```bash
npm run test:todos
npm run lint
npm run build
```

数据库测试使用开发依赖 PGlite 的内存 PostgreSQL，不读 `.env.local`，不访问正式 Supabase。

发布后用测试任务检查：

1. 创建「每天」，不完成今天的任务，切到明天：仍应看到任务。
2. 回到今天，把本次改到明天：今天不再补回，明天显示改期的这次和明天正常的一次。
3. 跳过一次，刷新：保持跳过，进度不计入；恢复后回到待办。
4. 选择「这次及以后」修改内容：此前任务不变，后续使用新内容。
5. 完成一次后停止后续重复：完成记录保留，再次刷新不会生成未来任务。
6. 周末创建「周一至周五」：第一条安排在下周一。Dashboard 与 Todo 的今天任务数应一致。
