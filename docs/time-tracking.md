# 时间记录与实际用时回顾

## 启用前的数据库更新

已有 Todo 3.0 数据库：在对应 Supabase 项目的 **SQL Editor** 中，复制并执行完整文件：

`lib/supabase/migrations/20261015_time_tracking.sql`

新数据库依次执行 `lib/supabase/schema.sql`、`lib/supabase/migrations/20261002_todo_recurrence.sql`，最后执行时间记录迁移。不要用重新建表替代旧库升级。

迁移新增 `time_records`、索引、RLS、校验触发器和五个 RPC，不删除或重写现有任务，支持重复执行。请先在测试项目验证并按自己的备份流程备份正式数据库。代码测试不代表正式数据库已经执行迁移。

数据库更新完成后，再发布前端；沿用现有两个 Supabase 环境变量，不需要新增密钥或后台服务。没有迁移时，时间功能会提示管理员更新数据库，不阻挡任务回顾。

## 使用流程

1. 从导航进入“时间记录”，填写活动名称及分类，按需选择任务；也可从每日待办的“记录时间”进入，自动带入任务。
2. 点击开始，休息时暂停，回来后继续。切换页面、关闭标签页或刷新不会停止服务端计时。
3. 活动结束后点击“结束并保存”。结束计时不会自动完成待办，需要单独勾选任务。
4. 忘记计时时使用“补记时间”，填写过去的起止时间，单次最多 24 小时。与已有片段或当前运行时段重叠时会拒绝保存，保留输入供调整。
5. 在“行动回顾”查看近 7 / 30 天的用时饼图，展开明细可查看构成。任务搜索、状态筛选不改变用时占比。

工作、学习、生活、其他为当前固定分类，不支持自定义分类。已保存记录可在时间记录页编辑或删除；删除会影响统计，不删除关联任务。放弃计时会删除尚未保存的这次计时，操作前需确认。

## 统计口径

- 只累计结束并保存的真实计时片段，暂停区间不计入；正在运行或暂停但未结束的计时均不进入饼图。
- 日期范围按当前设备时区的本地零点计算，包括今天。跨天记录与范围求交，只累计落在范围内的片段，不把整条记录归到开始日期。
- 占比 = 分类实际用时 ÷ 范围内总用时。没有记录时显示空状态，不伪造占比；百分比显示一位小数，四舍五入后总和可能略偏离 100%。
- 编辑计时记录的名称、分类或关联任务会保留原暂停片段。勾选“调整起止时间”才转为连续时段，界面会提示不再扣除旧暂停区间。
- 任务被删除时，时间记录仍保留，并保存原任务名称。时间记录不是任务完成时间流水，两个统计分别计算。

## 状态与数据边界

`TimeProvider` 放在工作区外壳内，以账号 ID 隔离，导航复用同一计时状态。`time_active` 提供服务端时间，显示计时以该时间加单调时钟增量计算，不用浏览器每秒累加作为存储结果。页面恢复可见或网络恢复时重新同步。

`time_records` 的 `segments` 保存已结束的片段，`running_since` 标记当前运行起点。数据库在暂停、继续、保存时更新状态；不需要每秒请求，也不需要后台定时器。忘记结束不会自动截断，请自行结束或编辑记录。

账号级事务锁与唯一索引保证每个账号最多一个未结束计时；版本号阻止旧页面覆盖较新操作。创建使用稳定 ID，响应丢失后先同步服务端状态再允许下一次操作。跨标签页仅发送账号范围的同步信号，不在本地存储记录内容。未实现跨设备实时订阅，可使用同步或刷新按钮读取最新内容。

RLS 限制记录只能由所属账号读写，关联任务也校验账号。RPC 使用调用者权限，不使用管理员密钥。记录分页读取，完整且数量一致后才发布统计；错误时明确提示，不把缺失数据当成零值。
