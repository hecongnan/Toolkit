# 前端设计与验证

本次前端重构参考 `emilkowalski/skills` 的 `apple-design` 与 `emil-design-eng`。技能安装在个人 Codex 技能目录，不作为生产依赖提交到项目。后端 API 与 Supabase 数据结构不变，无需再次执行 SQL。

## 设计方向

让个人工作区更专注、清晰和可预测。不是模仿一套系统外观，而是把排版层级、操作反馈、空间关系和无障碍规则落实到组件。

| Before | After | Why |
| --- | --- | --- |
| 深色硬编码和多色渐变 | 中性明暗主题、单一蓝色强调色、语义化状态颜色 | 强调内容，降低视觉噪声 |
| Google 字体构建依赖 | 平台系统字体 | 中文与系统观感一致，减少网络依赖 |
| 主题挂载后写回默认值 | 初次跟随系统，用户选择后记住偏好 | 避免覆盖已保存的选择 |
| 页面尺寸、控件样式分散 | 主题变量与共享基础组件 | 所有页面采用一致的层级与间距 |
| 通用 `transition`、高频操作动效 | 限定属性的短过渡，按压即时反馈 | 不让动画拖慢操作 |
| 非活动导航仍存在于焦点顺序 | 原生模态抽屉 | 非活动导航不可访问，打开时隔离背景 |
| 自制弹窗没有焦点边界 | 原生 `dialog` 加首选字段焦点、Tab 边界、焦点归还 | 键盘与读屏行为明确 |
| 手机操作依赖 hover | 触屏始终可见操作，44px 控件热区 | 不需要猜测隐藏操作的位置 |
| 保存和复制缺少完整反馈 | 保存锁、保留草稿、弹窗内错误、复制成功/失败提示 | 失败后可以继续操作 |

## 组件与规则

- `app/globals.css`：表面、文字、强调色、语义色、阴影、缓动的统一变量。
- `components/shell`：导航、顶栏、内容宽度、标题和跳转到主要内容的入口。
- `components/ui`：按钮、输入框、卡片、标签、空态、加载状态、原生对话框。
- 页面保留现有流程：概览、每日待办、学习资料、项目分析、AI 设置、登录与密码恢复。
- `components/dashboard`：概览各模块独立加载、错误恢复和数据保留；手机先展示待办，桌面使用两栏。
- 偶发弹窗使用短的淡入/位移，进入与退出遵循相同空间关系；没有新增拖拽手势或弹簧依赖。频繁列表操作不增加等待动画。
- 键盘打开弹窗不做位移动画；`prefers-reduced-motion` 去掉位移。`prefers-reduced-transparency` 使用不透明材料；`prefers-contrast: more` 加强边界。
- 仅精细指针使用悬停动作显隐，触屏始终显示任务操作。放大文字时，操作组允许换行。
- 旧组件中的 `teal` 工具类暂映射到统一蓝色以保持兼容，新组件优先使用语义变量；可以逐页迁移旧工具类，不影响数据层。

## 可重复验证

```bash
npm ci
npx playwright install chromium
npm run test:ui
npm run test:todos
npm run build
```

`test:ui` 自动构建并启动本地生产预览，使用虚假的 Supabase 地址、密钥和账号，并拦截外部请求；不会发送真实 AI 请求或写入真实数据库。不需要配置测试账号。运行前确保 3107 端口空闲。

测试覆盖：

- 五个工作区页面的桌面/手机、日间/夜间布局及运行时错误。
- 弹窗首选输入焦点、Tab/Shift+Tab 约束、Escape、焦点归还与立即重新打开。
- 手机导航的焦点约束、页面切换和窗口放大后关闭。
- 系统主题变化、手动主题选择和刷新后的持久化。
- 320px 小屏幕、44px 操作热区、减少动态效果、200% 字号。
- 学习资料失败后的草稿保留、重试，以及关闭动画期间快速重新新增时的独立草稿。
- 报告复制失败/成功反馈、关闭追问弹窗后保留草稿。
- 未登录时的登录、注册、密码恢复页面。
- 模拟触屏连续完成、慢请求乱序、单项保存失败与重试、空更新结果、逾期计数及跳过恢复。
- 完成操作不重新读取列表、后台删除刷新保留其他任务节点、成功提示不改变任务位置、旧读取不能覆盖新完成状态。
- 欢迎页的慢模块与失败模块隔离、单模块重试、刷新保留任务和报告、空账号与空日期区分、手机任务时间与查看入口。
- 登录和注册密码的触摸与键盘显示切换，保留输入和焦点，不触发表单提交。

截图与失败追踪放在被 Git 忽略的 `test-results/`。已有 Chromium 可通过 `TOOLKIT_TEST_BROWSER` 指定路径，正常开发无需设置。待办日期与数据库语义由独立的 `test:todos` 验证。

## 后续事项

### 移动端待办反馈

完成和恢复任务先更新本地状态，再保存到 Supabase。每项任务独立同步，可以连续勾选不同任务；同一项在保存期间不能重复提交。失败时只恢复该项，保留其他项的成功结果，并显示包含任务名称的错误。保存需返回一条实际更新的记录，避免权限限制或任务已被删除时误报成功。

完成操作不重新读取整个列表；已有后台请求通过请求序号作废，防止旧数据覆盖新状态。新增、编辑、删除和排序后的读取在后台进行，保留现有列表；首次加载、切换日期和加载失败后的重试显示加载状态。成功提示不占列表布局空间，五秒后消失，也可手动关闭。保留即时按压反馈，不添加任务移除等待动画。

同步期间暂时锁定日期和结构修改，避免重复计划的编辑、删除与完成请求相互覆盖；其他任务的完成按钮继续可用。数据库结构与重复计划规则不变，无需执行新的 SQL。

### 欢迎界面优化

以下改进已经实现，并通过隔离数据的浏览器测试与手机、桌面截图检查。模块加载逻辑与展示组件分开维护，不增加生产依赖。

| Before | After | Why |
| --- | --- | --- |
| 手机概览先显示三张统计卡，待办在其后 | 手机先显示今日待办，统计缩为三张紧凑摘要；桌面两栏 | 首屏直接帮助用户开始行动 |
| 新账号看到多个零值和空状态 | 空账号显示“创建第一条待办”，学习和 AI 设置为可选入口 | 减少首次使用的选择负担；有其他日期任务时不误判新账号 |
| 任一模块查询失败后，整个概览隐藏 | 每个模块独立加载和重试，首次加载使用静态占位，刷新保留现有内容 | 单个故障不影响其他功能，也不使列表突然清空 |
| 任务预览的圆圈像复选框，但不能点击；手机隐藏时间 | 整行是明确的查看入口，时间始终显示，标题可显示两行 | 让外观与行为一致，保留重要信息 |
| 密码始终遮蔽，登录与注册都显示“至少 6 位” | 44px 显示密码按钮，触摸保持输入焦点；登录提示输入密码，注册规则持续显示 | 方便手机核对输入，减少错误 |

浏览器自动化已覆盖 Chromium 的桌面与模拟触屏；仍建议在真实 iPhone/Safari 和 Android 上检查键盘弹出、系统日期选择器与网络较慢的场景。

本次安装的 Playwright 仅用于开发测试，不增加生产页面依赖。依赖审计发现既有 Next.js 14 及其部分依赖存在安全告警；修复建议涉及 Next.js 主版本升级，应单独验证 EdgeOne 的构建、认证与服务端路由兼容性，不能用一次 `npm audit fix --force` 混入视觉重构。
