# 前端设计与验证

当前产品是个人行动工作台，主线为“计划 → 执行 → 回顾”。界面统一使用已安装的 apple-design 与 emil-design-eng 指导：清晰层级、即时反馈、至少 44px 的移动端触控目标、稳定列表、键盘焦点与 reduced-motion。

| Before | After | Why |

## 交互约定

- 主导航只有四项，三条工作路径在首页连通。
- 日常任务完成不等待装饰动画。周计划勾选后原行留在原处，失败仅回滚该项。
- 周计划的状态、每日待办的编辑、回顾的结果来自同一份任务；跨页面会重新读取最新状态。
- 每日创建草稿仍可在周计划中恢复，反之亦然；未保存草稿的日期优先于新页面选中的日期，避免悄悄覆盖输入。
- 已完成或跳过的任务能回到每日待办管理；周视图不把跳过任务当成普通待完成任务。
- 加载失败不展示虚假的零值；后台刷新保留内容并标注上次结果，提供重试。
- 浅色和深色使用同一套语义颜色；不为频繁的键盘操作添加等待。

## 数据与统计边界

`useTaskRange` 按账号和日期范围读取，分页为 500 条并使用确定性排序；只有完整、去重数量与精确计数一致时才发布数据。失败不会用部分数据覆盖旧结果。请求序号使慢响应不能覆盖新日期范围。

重复任务仍由现有事务 RPC 生成。周计划补齐所选七天；回顾补齐现有规则支持的最近 30 天。回顾按计划日期和当前完成状态计算，包含今天，不宣称为实际完成时间统计；跳过项不计入分母。

## 验证

`npm run test:todos` 在内存 PostgreSQL 中覆盖原有重复、改期、停止、迁移重跑和 RLS。`npm run test:ui` 自动构建隔离预览，用虚假账号和 Supabase 请求夹具验证，禁止连接生产数据。

本轮增加了周计划 → 创建 → 每日执行 → 回顾的连通流程、周视图慢请求与失败恢复、回顾统计边界、503 条分页失败与重试、旧地址重定向、已移除 API、空状态以及 320 / 375px 大字号深色截图检查。

旧版本的设计与测试记录保存在 [历史设计记录](frontend-history.md)，其中涉及学习资料和 AI 的内容仅供历史查阅，不代表当前功能。
