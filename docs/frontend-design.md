# 前端设计与验证

当前产品是个人行动工作台，主线为“计划 → 执行 → 回顾”。界面统一使用已安装的 apple-design 与 emil-design-eng 指导：清晰层级、即时反馈、至少 44px 的移动端触控目标、稳定列表、键盘焦点与 reduced-motion。

## 信息架构

| Before | After | Why |
| --- | --- | --- |
| 学习资料、项目分析、AI 设置与任务各自独立 | 概览、每日待办、一周计划、行动回顾共用任务 | 让每个入口都能推动实际行动 |
| 依赖配置 AI 才能使用部分主要模块 | 核心流程只需要登录 | 降低使用门槛和维护成本 |
| 概览统计多个模块，行动入口分散 | 突出今日任务，展示计划、执行、回顾三条路径 | 明确今天先做什么 |
| 学习资料区域与待办重复记录进度 | 一周计划选择日期并复用任务创建弹窗 | 只维护一次内容 |
| 报告与历史占据长页面 | 回顾按日期展示进度，搜索后可以返回任务编辑 | 让回顾直接服务下一次安排 |
| 请求不完整容易给出局部计数 | 分页确认完整范围后发布统计，失败显示明确状态 | 结果可被信任 |
| 删除旧模块可能连带清库 | 移除运行代码，保留现有数据库旧数据 | 保留找回历史资料的机会 |

## 交互约定

- 主导航包含概览、每日待办、一周计划、时间记录和行动回顾；时间功能与任务、回顾互相连通。
- 日常任务完成不等待装饰动画。周计划勾选后原行留在原处，失败仅回滚该项。
- 周计划的状态、每日待办的编辑、回顾的结果来自同一份任务；跨页面会重新读取最新状态。
- 每日创建草稿仍可在周计划中恢复，反之亦然；未保存草稿的日期优先于新页面选中的日期，避免悄悄覆盖输入。
- 已完成或跳过的任务能回到每日待办管理；周视图不把跳过任务当成普通待完成任务。
- 加载失败不展示虚假的零值；后台刷新保留内容并标注上次结果，提供重试。
- 浅色和深色使用同一套语义颜色；不为频繁的键盘操作添加等待。

## 数据与统计边界

`useTaskRange` 按账号和日期范围读取，分页为 500 条并使用确定性排序；只有完整、去重数量与精确计数一致时才发布数据。失败不会用部分数据覆盖旧结果。请求序号使慢响应不能覆盖新日期范围。

重复任务仍由现有事务 RPC 生成。周计划补齐所选七天；回顾补齐现有规则支持的最近 30 天。回顾按计划日期和当前完成状态计算，包含今天，不宣称为实际完成时间统计；跳过项不计入分母。

## 验证

`npm run test:todos` 在内存 PostgreSQL 中覆盖原有重复、改期、停止、迁移重跑和 RLS。`npm run test:ui` 自动构建隔离预览，用虚假账号和 Supabase 请求夹具验证，禁止连接生产数据。

本轮增加了周计划 → 创建 → 每日执行 → 回顾的连通流程、周视图慢请求与失败恢复、回顾统计边界、503 条分页失败与重试、旧地址重定向、已移除 API、空状态以及 320 / 375px 大字号深色截图检查。

旧版本的设计与测试记录保存在 [历史设计记录](frontend-history.md)，其中涉及学习资料和 AI 的内容仅供历史查阅，不代表当前功能。

## 时间记录与饼图设计（2026-10-15）

继续应用 apple-design 与 emil-design-eng，优先即时反馈、明确计时状态和稳定布局，不加入阻碍开始、暂停和保存的装饰动画。

| Before | After | Why |
| --- | --- | --- |
| 回顾只有任务完成比例 | 增加实际用时饼图、时长、百分比与明细 | 区分做完多少与投入多久，不把任务数量当作时间 |
| 任务与用时没有关联入口 | 任务菜单可进入时间记录，回顾可进入计时页 | 避免重复输入，形成执行到回顾的闭环 |
| 切页后看不到计时状态 | 工作区顶部显示当前计时及返回入口 | 状态持续可见，不需要守在计时页面 |
| 手机大字号下饼图的隐式网格可能撑宽页面 | 单列使用 minmax(0, 1fr)，图表受容器宽度约束 | 保留完整图表和图例，不靠裁切遮盖溢出 |
| 日期时间合并控件在窄屏过宽 | 日期和时间分别输入，小屏单列排列 | 支持 320px 与大字号，不挤压触控区域 |
| 保存失败可能让人重填或重复点击 | 保留输入、锁定提交、用同一 ID 安全重试 | 网络不稳定时仍可恢复，不产生重复记录 |

饼图配有可访问名称和文字图例，颜色不是唯一的信息来源。弹窗复用现有焦点管理、误关闭保护和 reduced-motion 样式；触控目标至少 44px。真实手机键盘与输入法仍需人工验证。
