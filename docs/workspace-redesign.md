# 从工具集合到行动工作台

本轮按用户要求移除学习资料、GitHub 项目分析、AI 设置、分析/追问接口及相关 SDK 和 Markdown 展示依赖。产品围绕个人任务执行展开；不是在原来的独立模块旁再增加新入口。

本文记录该次工作区重构的范围，下面的“无需新迁移”仅适用于那次重构。后续增加的时间记录使用独立 `time_records` 表，启用前需执行 `20261015_time_tracking.sql`，详见 [时间记录与实际用时回顾](time-tracking.md)。当前安装与升级顺序以 README 为准。

## 使用路径

1. 在一周计划选择日期，安排可执行的小任务。
2. 进入每日待办，完成、排序、编辑、改期，或处理逾期与重复任务。
3. 在行动回顾查看近 7 / 30 天当前进度，定位具体任务，再调整安排。

首页回答“今天先做什么”，并连接以上三个页面。周计划和回顾中的任务链接携带日期与搜索条件，进入每日待办后可直接定位。

## 本轮边界

- 不增加数据库表或新的迁移。已有 Todo 3.0 数据库可以直接使用。
- 旧学习资料和报告不会自动转换成任务，避免把收藏误变为待办、制造负担。
- 现有数据库中的 materials、analysis_reports、analysis_chats 保留，新应用不再读写。需要查看旧资料时，可由账号所有者在 Supabase 导出对应 user_id 的记录；未运行任何清库命令。
- 新安装的 schema.sql 仅创建任务基线，再执行原有重复任务迁移；不要重跑该脚本来升级现有库。
- 旧链接 /learning → /week、/github → /review、/settings → /，保留书签可达性。
- 原有浏览器学习资料草稿和 AI 配置不再读取；没有批量清理 localStorage 或 sessionStorage。
- 运行时只需要 Supabase 的两个公开环境变量。部署平台上旧的 AI/GitHub token 不再使用，可由站点所有者移除。

## 统计定义与限制

回顾展示任务的计划日期及当前完成状态，不表示实际完成时间，也不是不可变的历史流水。改期后归入新日期，删除后不计入统计，跳过不计入完成比例。没有任务时完成比例显示“—”。

近 30 天重复任务沿用现有规则补齐。周一至周五不自动处理法定调休。单次改期仍保留后续重复规则。

范围查询按稳定顺序分页。只有完整结果才显示总计；分页失败或计数变化会要求刷新，避免局部列表被当作全部结果。多端同时增删或改期时仍可能需要手动刷新，不提供数据库快照隔离或实时订阅保证。

未实现目标/项目分组、反思笔记、番茄钟、推送提醒或 AI 功能；这些不作为当前页面的空入口展示。

## 恢复与发布

源代码删除可从 Git 历史恢复。旧数据库表和数据未删除。当前重构不会自动提交、推送或部署；发布前检查差异和测试，再按站点现有 Git 集成发布。
